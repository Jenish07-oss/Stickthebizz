1. Executive Summary & Purpose

StickTheBizz is a modern, privacy-first customer loyalty SaaS platform built specifically for Indian local merchants (Chai stalls, bakeries, kirana stores, cafes). The platform eliminates traditional plastic loyalty cards, paper punch slips, and complex app downloads. Instead, it pairs a physical 5x7 Acrylic Counter QR Standee with an instant browser-based Digital Loyalty Pass accessed via any smartphone camera.

This report documents the transformation of the codebase from an initial mock/demo prototype into a 100% live, production-hardened platform connected to a real Supabase database, real Google SMTP OTP delivery, anti-fraud daily visit guards, an in-app Camera QR scanner, and dynamic monthly standee rotation.

3. Core Architecture & System Modules

A. Dynamic Counter QR Standee & 30-Day Rotation

The QR standee component (components/CounterQR.tsx) renders a photorealistic 3D acrylic tabletop standee with reflections and depth shadows. The embedded QR code points to /s/[slug]?cycle=[token].

  • Shop Owner Customization: In the Cashier Terminal (/owner/dashboard), owners can edit Store Name, Minimum Bill Spend (₹), Visits Required, Reward Name, and Streak Expiry Period (e.g., 30 Days). All updates instantly redraw the printable standee artwork.
  • Monthly Standee Rotation: When a new month begins or an owner suspects fraud, clicking "Rotate / Refresh Monthly QR" generates a new token in Supabase (qr_token), expiring any old standees.
  • Print Optimization: Built-in window.print() CSS media queries format the standee for standard 5x7 inch acrylic counter frames.

B. Daily Anti-Fraud Check-In Guard (12:00:00 AM IST)

To prevent customers from scanning the counter standee multiple times in one day or sharing the link via WhatsApp, the platform enforces strict 1-scan-per-calendar-day rules:

  • Server Action: submitScan() calculates the exact calendar date in Asia/Kolkata timezone (IST, UTC+5:30) in YYYY-MM-DD format.
  • PostgreSQL Constraint: The visits table has a unique composite constraint: CONSTRAINT unique_daily_scan UNIQUE (customer_id, merchant_id, visit_date_ist).
  • Client Experience: When locked, the customer's pass disables the stamp button and displays a live ticking countdown: "Today's visit verified! Next stamp unlocks at 12:00:00 AM IST."

5. Database Schema & Row-Level Security (RLS)

The Supabase PostgreSQL database uses three core tables with hardened RLS policies:

-- 1. MERCHANTS TABLE
CREATE TABLE IF NOT EXISTS public.merchants (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  owner_id UUID REFERENCES auth.users(id) ON DELETE SET NULL,
  name TEXT NOT NULL,
  slug TEXT UNIQUE NOT NULL,
  category TEXT DEFAULT 'Cafe / Chai',
  min_spend NUMERIC DEFAULT 100,
  visits_required INT DEFAULT 10,
  reward_name TEXT NOT NULL,
  validity_days INT DEFAULT 30,
  redemption_pin TEXT DEFAULT '8492',
  qr_token TEXT DEFAULT 'active',
  created_at TIMESTAMPTZ DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- 2. CUSTOMERS TABLE
CREATE TABLE IF NOT EXISTS public.customers (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  auth_id UUID REFERENCES auth.users(id) ON DELETE SET NULL,
  phone TEXT UNIQUE NOT NULL,
  email TEXT,
  full_name TEXT,
  created_at TIMESTAMPTZ DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- 3. VISITS TABLE (WITH STRICT DAILY SCAN CONSTRAINT)
CREATE TABLE IF NOT EXISTS public.visits (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  customer_id UUID NOT NULL REFERENCES public.customers(id) ON DELETE CASCADE,
  merchant_id UUID NOT NULL REFERENCES public.merchants(id) ON DELETE CASCADE,
  visit_date_ist TEXT NOT NULL, -- Format: 'YYYY-MM-DD' (Asia/Kolkata)
  bill_amount NUMERIC DEFAULT 100,
  status TEXT DEFAULT 'PENDING' CHECK (status IN ('PENDING', 'APPROVED', 'REJECTED', 'REDEEMED')),
  created_at TIMESTAMPTZ DEFAULT timezone('utc'::text, now()) NOT NULL,
  CONSTRAINT unique_daily_scan UNIQUE (customer_id, merchant_id, visit_date_ist)
);

-- 4. REALTIME REPLICATION (SAFE IDEMPOTENT PUBLICATION)
DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime ADD TABLE public.visits;
EXCEPTION
  WHEN duplicate_object THEN NULL;
END $$;
